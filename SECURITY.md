# Security policy

## Reporting a vulnerability

Do not open a public issue for a security problem. Report it privately to security@fairaccessshield.com.
Say which version is affected, how to reproduce the problem, and what impact you see; a proof
of concept helps. No encryption key is published; ask for one by email first if the report
needs it.

## What to expect

- An acknowledgement as soon as a maintainer reads the report, and a first assessment of
  severity and scope after it is reproduced.
- Coordinated disclosure: we ask that details stay private until a fix is released or 90 days
  have passed since the report, whichever comes first, and we credit the reporter in the
  release notes unless they prefer otherwise.
- Fixes go into a new release of the latest version; older versions are not patched unless a
  release note says so.

## Scope

The code in this repository and the release artefacts built from it. Vulnerabilities in a
dependency are reported upstream; tell us as well so the dependency can be updated or
replaced. Hosted services run by Andrew Briscoe have their own contact if one is published.
